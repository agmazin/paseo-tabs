# Проверка 0.3.0

25.10.2026. Тестовый демон 6793, Paseo 0.13.0. Основные вкладки Александра не трогались.
TypeScript и 10 тестов прошли. Архивирование с работающим потомком проверено на демоне 6786
в сценарии Диалогов 0.9.0 (демон 0.12.0, клиент из установленного приложения 0.13.0).

`RUNNING=6a510037-040d-45ec-a68e-f1f93299b4fa node tests/browser/close-without-archive.mjs`
прошёл: крестик, Cmd+W, средний клик, меню "Закрыть", слева, справа, другие.
CLI подтверждал `Archived=false`, `Status=running`; строка оставалась в Диалогах,
после клика вкладка открывалась. Подтверждений архивации и ошибок страницы не было.
Скрытие пережило перезагрузку страницы и закрытие/повторный запуск процесса Chrome
с тем же отдельным профилем. Профиль после проверки удалён.

В родном persist merge стора Paseo 0.13 восстанавливаются раскладка и pinnedAgentIds,
но hiddenAgentIds не восстанавливаются. Поэтому список хранится в localStorage плагина.
Проверка полного перезапуска относится к отдельному браузерному клиенту с тем же
хранилищем. Приложение Александра и основной демон не перезапускались.

`close-mixed.mjs` прошёл: массовое закрытие агентов вместе с тестовым терминалом
предлагает родное подтверждение терминала без архивации агентов; отмена оставляет терминал.
Тестовый терминал после проверки закрыт CLI.
`close-fallback.mjs` прошёл: подмена только ответа fetch для поиска модуля (без изменения
самого выполняемого бандла) даёт одно предупреждение, перехват не устанавливается,
родное закрытие одноразового idle-агента по-прежнему архивирует его.
После основной проверки работающий тестовый агент остановлен; fallback затем архивировал его.

Снимки: `shots/0.3.0/running-closed.png`, `browser-restarted-hidden.png`, `only-current-tab.png`.

## Основной демон

Выложены теги v0.3.0 (051004b) и v0.9.0 (02de706) через штатные release-клоны.
Демон не перезапускался: PID supervisor 1887, worker 1889. Оба плагина running.
`getPluginCatalog()` основного демона содержит новый адаптер закрытия и меню архивации;
хеши реально выдаваемых клиентских бандлов записаны в deployment-0.3.0.json.
В логе запуска оба дошли до Plugin ready, ошибок загрузки плагинов нет.
При запуске серверной части Диалогов Electron выводит системную строку
SecCodeCopyGuestWithAttributes ENOENT, после неё плагин успешно переходит в ready.
HTTP-корень основного демона не обслуживает веб-интерфейс, поэтому проверка его каталога
выполнена штатным DaemonClient через локальную авторизацию; действия над его чатами не выполнялись.
